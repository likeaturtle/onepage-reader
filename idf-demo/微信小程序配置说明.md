# 墨程CalCal 微信小程序配置说明

本文说明如何把 `idf-demo/miniprogram`（墨程CalCal）导入微信开发者工具，并配置登录服务。适用对象是
本地开发、真机调试和正式部署；现有网页 `web/index.html` 和固件都不需要改动。

> **最短路径**：只想先把小程序跑起来、测试云端日程和 BLE，用「开发模式登录」即可，
> 不需要申请 AppID。只有要测真实微信登录时，才需要配置 `WX_APPID` / `WX_SECRET`。

---

## 1. 组件与目录

```text
idf-demo/
├── miniprogram/                 微信小程序（导入开发者工具的就是这个目录）
│   ├── config.js                apiBase、devLogin、设备名前缀
│   ├── app.json / project.config.json
│   └── pages/                   login / index / profile
└── server/                      登录 + 云端日程服务
    ├── .env                     本地配置（gitignore，不提交）
    ├── .env.example             配置模板
    └── src/
```

服务端负责：

- `wx.login` 的 code 换 openid；
- 签发登录 token；
- 保存昵称、头像；
- 按用户保存云端日程（`data/events.json`）。

小程序里只放 `apiBase`，**绝不要放 `WX_SECRET`**。

---

## 2. 环境要求

- Node.js **22+**（服务端使用 `--env-file-if-exists` 与内置 `fetch`）；
- 微信开发者工具（macOS 默认安装路径 `/Applications/wechatwebdevtools.app`）；
- 一个能扫码登录开发者工具的微信账号；
- 可选：已注册小程序的 AppID / AppSecret（只有真实微信登录才需要）。

---

## 3. 启动登录服务

```bash
cd /Users/fujd/Desktop/onepage-reader/idf-demo/server
cp -n .env.example .env      # 已存在时会保留，不会覆盖
npm start
```

正常输出：

```text
[server] listening on http://0.0.0.0:8787
[server] wechat login: configured        # 或 NOT configured
[server] dev login: enabled
```

检查服务：

```bash
curl http://127.0.0.1:8787/api/health
```

```json
{"ok":true,"wechat":false,"devLogin":true}
```

- `wechat:false`：还没配置 AppID/Secret，仍可用开发模式登录；
- `wechat:true`：真实微信登录已就绪；
- `devLogin:true`：开发模式登录已开启。

### 3.1 `.env` 配置项

| 变量 | 作用 | 本地建议 |
|:---|:---|:---|
| `PORT` | 服务端口，默认 `8787` | 保持 8787，和 `config.js` 一致 |
| `HOST` | 监听地址 | `0.0.0.0`，便于手机访问 |
| `WX_APPID` | 小程序 AppID | 真实登录时填写 |
| `WX_SECRET` | 小程序 AppSecret | 只填服务端，不要发给别人 |
| `ALLOW_DEV_LOGIN` | 是否允许 `{"dev":true}` 免微信登录 | 本地 `1`，生产 `0` |
| `SESSION_SECRET` | 登录 token 的 HMAC 密钥 | 生产用 `openssl rand -hex 32` 生成 |
| `TOKEN_TTL_DAYS` | 登录有效期，默认 7 天 | 按需 |
| `DATA_DIR` | 用户/日程数据目录 | 默认 `./data` |
| `MAX_AVATAR_BYTES` | 头像大小上限 | 默认 512 KB |
| `CORS_ORIGIN` | 浏览器调试 CORS | 默认 `*` |

### 3.2 改完 `.env` 必须重启

配置只在服务进程启动时读取，`npm start` 不会监听 `.env` 变化。修改后：

1. 在运行 `npm start` 的终端按 `Ctrl+C`；
2. 重新执行 `npm start`；
3. 再请求一次 `/api/health` 确认 `wechat` 变成 `true`。

**这是“明明配了 AppID，登录仍提示未配置”的最常见原因**：旧进程还在用启动时的空配置。

### 3.3 已经配置了，为什么还提示“服务端未配置微信登录”？

按顺序排查：

1. **看当前进程实际读到的配置**：

   ```bash
   curl http://127.0.0.1:8787/api/health
   ```

   如果返回 `"wechat":false`，说明 8787 上的进程没有读到 `WX_APPID/WX_SECRET`。
   即使 `.env` 文件内容是对的，也要**重启** `npm start`。配置只在启动时读取。

2. 确认改的是 `server/.env`，不是 `server/.env.example`：

   ```bash
   ls -l server/.env
   ```

3. 确认文件在 `server/` 目录，`npm start` 也是在该目录执行的。若从仓库根目录
   直接运行 `node idf-demo/server/src/server.js`，`.env` 不会被自动加载。

4. 确认没有多余空格、引号或中文全角符号：

   ```dotenv
   WX_APPID=wx1234567890abcdef
   WX_SECRET=0123456789abcdef0123456789abcdef
   ```

   `WX_APPID= wx...`（等号后有空格）和 `WX_APPID="wx..."`（带引号）都可能导致
   读取不到预期值。

5. 确认 `WX_APPID` 与开发者工具里项目的 AppID 完全一致，`WX_SECRET` 没有复制错。

6. 重启后再次检查：

   ```bash
   curl http://127.0.0.1:8787/api/health
   # {"ok":true,"wechat":true,"devLogin":true}
   ```

   看到 `"wechat":true` 后，回开发者工具重新编译并点「微信一键登录」。

如果暂时不想处理 AppID，直接点「开发模式登录」也可以继续测试其余功能。

## 4. 导入微信开发者工具

### 4.1 打开工具

```bash
open -a wechatwebdevtools
```

用微信扫码登录。

### 4.2 导入项目

1. 点左侧 **+** → **导入项目**；
2. **目录**选择：

   ```text
   /Users/fujd/Desktop/onepage-reader/idf-demo/miniprogram
   ```

   注意：必须选到包含 `app.json`、`project.config.json` 的这一层，不是 `idf-demo`；
3. **项目名称**随意，例如 `mocheng-calcal`；
4. **AppID**：
   - 没有正式 AppID：选 **测试号**（项目当前可能是 `touristappid`）；
   - 有正式 AppID：填写自己的 AppID，并确保和服务端 `WX_APPID` 一致；
5. 后端服务选择 **不使用云服务**；
6. 点 **确定**。

### 4.3 关闭域名校验

导入后：**详情 → 本地设置**，勾选：

> 不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书

`miniprogram/config.js` 默认接口是：

```js
apiBase: 'http://127.0.0.1:8787'
```

开发者工具访问本机 HTTP 服务需要这个开关。

### 4.4 编译并登录

编译完成后进入登录页。此时有两种选择：

- 只用本地开发：点 **开发模式登录**；
- 测真实微信身份：先完成第 5 节的 AppID 配置，再点 **微信一键登录**。

## 5. 两种登录方式

### 5.1 开发模式登录（本地推荐）

前提：

- 服务端已启动；
- `server/.env` 中 `ALLOW_DEV_LOGIN=1`；
- 当前不是正式发布版（release 版会隐藏这个按钮）。

点击后调用：

```http
POST /api/login
{"dev":true}
```

服务端创建一个固定的 `dev-local` 用户。适合：

- 没有 AppID 时跑通界面；
- 测试云端日程的增删改查；
- 测试 BLE 扫描/连接/同步；
- 测试头像昵称。

注意：所有开发者共用这个 `dev-local` 账号，**不要用于正式环境**。

### 5.2 微信一键登录（真实身份）

需要同时满足：

1. `server/.env`：

   ```dotenv
   WX_APPID=你的小程序AppID
   WX_SECRET=你的小程序AppSecret
   ALLOW_DEV_LOGIN=0
   ```

2. `miniprogram/project.config.json`（或开发者工具「详情 → 基本信息」）里的 AppID
   与服务端 `WX_APPID` **完全一致**；
3. 改完 `.env` 后**重启** `npm start`；
4. 开发者工具里重新编译，再点 **微信一键登录**。

流程：

```text
小程序 wx.login() → code
        ↓ HTTPS
服务端 /api/login → code2session（AppID + AppSecret）
        ↓
openid → 用户记录 → 签发自己的 token
        ↓
小程序保存 token，后续 /api/me、/api/events 带 Bearer token
```

`AppSecret` 只存在服务端；小程序代码里没有任何 Secret。

## 6. 常见错误

| 现象 | 原因 | 处理 |
|:---|:---|:---|
| `服务端未配置微信登录，请先填写 WX_APPID / WX_SECRET` | 旧进程没读到新 `.env`，或 `.env` 不在 `server/`，或值为空 | 重启服务；`curl /api/health` 确认 `wechat:true` |
| `无法连接服务器，请检查网络与 apiBase；真机请使用电脑局域网地址` | 服务端没启动、端口不对、真机用了 `127.0.0.1` | 启动 `npm start`；真机改成电脑局域网 IP（见 7.1） |
| `服务端 AppID / Secret 配置不正确` | AppID 与 AppSecret 不匹配，或复制时多了空格 | 到公众平台重新复制；确认没有引号/空格 |
| `登录凭证已失效，请重新登录` | `wx.login` 的 code 一次性、已过期 | 重新点一次登录 |
| `登录太频繁，请稍后再试` | 触发登录限流（30 次/分钟/IP） | 等一分钟 |
| `不在以下 request 合法域名列表` | 没勾选“不校验合法域名”，或真机/生产未配置 HTTPS 域名 | 本地勾选开关；生产配置 `request 合法域名` |
| 看不到「开发模式登录」 | 版本是 release，或 `ALLOW_DEV_LOGIN=0` | 用开发版/体验版；本地改回 `1` 并重启 |
| 扫描不到 `Mochen CalCal` | 设备还是旧固件、手机缓存了旧名字、或过滤器未更新 | 烧写新固件；忽略旧设备并重启蓝牙；打开“显示全部蓝牙设备”确认 |
| `AppID 无效` | 导入时选了测试号/游客模式 | 换成正式 AppID，或改用开发模式登录 |
| 页面空白/编译报错 | 导入目录选错 | 重新导入 `idf-demo/miniprogram` |

## 7. 真机与 BLE

开发者工具**模拟器不支持 BLE**，只能看登录、云端日程和页面样式。

真机测试：

1. 手机和电脑连同一个 Wi-Fi；
2. 把 [`config.js`](miniprogram/config.js) 的 `apiBase` 改成电脑局域网地址：

   ```js
   apiBase: 'http://192.168.1.20:8787'
   ```

   `127.0.0.1` 在手机上指向手机自己，连不到电脑；
3. 开发者工具点 **真机调试** 或 **预览**，手机微信扫码；
4. 手机微信允许蓝牙权限；
5. 按设备 POWER 唤醒，再在小程序里扫描 `Mochen CalCal`。

### 7.1 关于真机顶部的红色报错“无法连接服务器”

截图里的红色报错**不是排版问题**，而是手机访问不到服务端：

- `miniprogram/config.js` 默认 `apiBase` 是 `http://127.0.0.1:8787`；
- 在真机上，`127.0.0.1` 指向**手机自己**，不是你的电脑；
- 必须改成电脑的局域网 IP。

先查电脑的局域网 IP（Wi-Fi）：

```bash
ipconfig getifaddr en0
# 例如输出 192.168.1.20
```

然后修改 [`config.js`](miniprogram/config.js)：

```js
apiBase: 'http://192.168.1.20:8787'
```

按下面顺序确认：

1. 手机和电脑连的是**同一个 Wi-Fi**（不要用访客网络，避免 AP 隔离）；
2. 服务端仍在运行，且监听 `0.0.0.0:8787`：

   ```bash
   cd idf-demo/server
   npm start
   ```

3. 用手机浏览器打开：

   ```text
   http://192.168.1.20:8787/api/health
   ```

   应返回类似：

   ```json
   {"ok":true,"wechat":true,"devLogin":true}
   ```

   如果手机浏览器打不开，先解决网络/防火墙/端口问题，小程序一定也连不上。

4. 回微信开发者工具重新点「编译」，再重新预览/真机调试，让手机加载新的
   `config.js`。

如果手机浏览器能打开健康检查，但小程序仍提示域名/HTTPS 问题，说明被微信的合法域名
校验拦截了，需要改用 HTTPS 反向代理或部署到已配置 `request 合法域名` 的服务器。

真机访问非 HTTPS 域名可能仍受微信域名校验限制。若真机调试被拦截，改用：

- 内网 HTTPS 反向代理；或
- 部署到有 HTTPS 域名的服务器，并在微信后台配置 `request 合法域名`。

首次使用云端功能时，需要**先连接一次设备**，把设备上已有日程导入云端；之后不带设备
也能在手机上看。

### 7.2 设备广播名已改为 Mochen CalCal

固件已把 BLE 广播名从 `OnePage Calendar` 改为 **`Mochen CalCal`**，同时更新的还有：

- 扫描响应里的设备名、GAP 设备名；
- `hello` 消息和 INFO 特征里的 `name`；
- `sdkconfig.defaults` 里的 `CONFIG_BT_NIMBLE_SVC_GAP_DEVICE_NAME`。

**必须重新烧写固件，广播名才会变。** 只执行 `idf.py build` 不够：

```bash
cd /Users/fujd/Desktop/onepage-reader/idf-demo
source /Users/fujd/.espressif/tools/activate_idf_v6.1.sh
idf.py -p /dev/cu.usbmodemXXXX flash monitor
```

小程序侧已经同步：

- [`config.js`](miniprogram/config.js) 的 `deviceNamePrefix` 改为 `'Mochen'`；
- 扫描默认只显示名字包含 `Mochen` 的设备；
- 设备信息、错误提示、fallback 名称都改为 `Mochen CalCal`。

烧写后如果扫描不到，按顺序检查：

1. 设备是否已经烧写新固件（仍显示 `OnePage Calendar` 说明还是旧固件）；
2. 手机系统蓝牙里是否缓存了旧设备，忽略/取消旧设备后关闭再打开蓝牙；
3. 小程序里打开「显示全部蓝牙设备」手动确认设备是否在广播；
4. 设备是否按 POWER 唤醒，是否还在广播状态。

网页版是按 service UUID 过滤的，不依赖广播名，所以新旧名字都能连接；页面提示已经改为
`Mochen CalCal`。

以后如果再次改名，需要同步以下位置：

1. [`ble_calendar.c`](components/ble_calendar/src/ble_calendar.c) 的 `DEVICE_NAME`，
   以及 INFO / hello 里的 `name`；
2. [`sdkconfig.defaults`](sdkconfig.defaults) 的
   `CONFIG_BT_NIMBLE_SVC_GAP_DEVICE_NAME`；本地 `sdkconfig` 是 gitignore 的，
   也要同步修改，否则当前构建仍用旧值；
3. [`miniprogram/config.js`](miniprogram/config.js) 的 `deviceNamePrefix`；
4. 小程序/网页的 fallback 文案、[`docs/ble-protocol.md`](docs/ble-protocol.md) 和测试 mock；
5. 重新 `idf.py build` 并烧写。

## 8. 数据与安全

- 登录只用于识别账号；BLE 连接本身不需要登录，但当前版本主页面要求登录，
  因为日程列表来自“我的云端日程”；
- 云端数据保存在 `server/data/`（`users.json`、`events.json`、`avatars/`）；
- `.env` 已被 `.gitignore` 忽略，不要把 AppSecret 提交到仓库或发到聊天里；
- 生产环境必须：
  - `ALLOW_DEV_LOGIN=0`；
  - `SESSION_SECRET` 换成随机值；
  - 使用 HTTPS；
  - 配置微信后台 `request 合法域名`。
